# 多语言交互回归矩阵

用于现有官网、数据看板和多视图页面的验收。它补充内容翻译覆盖表，不取代源文版本、审核状态和路由规则检查。

## 建立本轮范围

记录当前提交/部署标识、环境、URL、语言、视图、浏览器、宽度及数据时点。语言与视图来自项目当前可达路由和配置；未开放语言单列锁定/回退用例，不能为了凑齐矩阵开放路由。

选择能覆盖项目断点与实际使用的宽度，包含受影响断点两侧、最窄支持宽度和较长译文。需要无障碍验收时补充键盘、缩放、屏幕阅读器与 reduced-motion；不要把视口模拟说成真机或辅助技术实测。

默认对本次范围中的语言 × 视图 × 宽度建立基础页面检查。交互用例按组件适用范围展开；无轮播的页面不假装跑了轮播测试。大矩阵可以基于改动风险做分层抽样，但要列出未覆盖组合、选择理由与残余风险，不能把抽样写成全覆盖。

用 [../assets/regression-plan.example.json](../assets/regression-plan.example.json) 表达语言、视图、宽度和场景，并运行 `python3 scripts/build_regression_matrix.py plan.json --output matrix.csv`。`locales`、`views` 和 `viewport_widths` 指定本轮维度；每个场景必须有唯一 `id` 与具体 `expected`，可用其 `locales` / `views` 子集限制适用范围。标识使用字母、数字、点、短横线或下划线；显示名称与实际 URL 另记在证据里。示例的宽泛场景应按项目细化为可独立判定的用例，尤其把失败、空数据、慢加载和重试分别留证。输出是待测清单，所有行初始为 `NOT_RUN`。脚本不抓取页面、不注入译文、不生成通过证据。

## 场景与判断标准

| 场景 | 操作 | 核验重点 |
| --- | --- | --- |
| 基础页面 | 直接打开、刷新、深链接 | 正确语言与视图、标题/导航/正文一致、长译文不遮挡、无横向溢出、资源与内部链接正确 |
| 语言切换 | 当前页切换语言，再刷新及后退/前进 | 保留项目规定的视图、筛选与锚点；目标不可用时遵循现有回退/锁定；不遗留旧语言标签或 URL 状态 |
| 加载与失败 | 观察慢加载、超时、失败、空数据、重试 | 清晰区分加载中、真实零值、无数据、失败与旧快照；错误提示已本地化；重试恢复且不重复触发写操作 |
| 轮播/分页 | 前后移动、首末边界、快速连点；适用时检查自动播放 | 顺序与数量正确、内容和指示器一致、切语言不串项、移动端不被遮挡；按项目约定验证键盘、暂停与 reduced-motion |
| 重复与中断 | 连点、切视图中途切语言、取消/关闭、返回 | 最后一次操作决定当前状态，旧请求不覆盖新结果；无重复事件、残留遮罩或历史栈异常 |
| 数据一致性 | 对照源响应、页面、其他语言和视图 | 同一指标、过滤器、日期区间、时区、单位与数据版本对应；展示格式可本地化，值与含义不能意外变化 |

只在任务允许的本地/预览环境用已有测试机制模拟网络失败或固定数据。生产检查优先被动观察；若需故障注入、提交表单、修改数据或触发外部动作，先确认权限。测试数据必须明确标记，不能替代真实页面验收或真实数据披露。

动态数据对比应固定同一快照或记录两次采集时间。允许的时延、舍入与汇总规则从项目定义取得；不硬编码“所有值完全相等”，也不把不同时间的数据差异误报为翻译 bug。混合真实数据、快照、演示数据时分别标记来源、更新时间和缺失状态。

## 逐行留证据

每行记录 `case_id, locale, view, viewport_width, scenario, expected, status, evidence, observed, tested_at, environment, revision, browser, data_snapshot, reason`。状态使用：
- `PASS`：按本行条件实际执行，观察符合预期，证据可追溯。
- `FAIL`：实际执行且与预期不符，记录复现步骤和影响。
- `BLOCKED`：尝试执行但被权限、网络、环境或数据等阻塞，写明原因。
- `NOT_RUN`：尚未执行，不纳入通过数。
- `NOT_APPLICABLE`：当前范围确实不适用，写明依据，不为降低失败率而使用。

证据可为测试日志、截图/视频或网络观察；保留可定位的时间和路径，去除账号、cookie、密钥及私人数据。`case_id` 只在当前矩阵内唯一；跨文件汇总使用计划文件标识/版本与 `case_id` 的组合键，重跑另记运行批次并保留历史，把最终结果与失败首次发现分开。生成命令失败时，可能留下不完整的新 CSV，不能当成有效计划；已有结果不会被覆盖。

## 交付判定

交付已覆盖组合与通过/失败/受阻/未执行/不适用数、关键缺陷、未测范围、数据和环境限制。高风险流程失败或重要组合未测试时，不能宣告整体验收通过。修复后复测失败用例及受影响的语言/视图/宽度，重新核对构建与真实页面。

内容翻译完整、语言审校完成、交互回归通过、代码已合并和生产已上线分别给结论。本文件及矩阵不提供发布授权。
